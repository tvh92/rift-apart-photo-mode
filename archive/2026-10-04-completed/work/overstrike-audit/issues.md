# Overstrike / Rift Apart issue audit

Audit date: 2026-10-04. Target: installed Overstrike 1.8.1 and Steam RCRA build 23987138 (provided in task context). Scope: current public Overstrike GitHub issues/releases/docs and likely TOC/stale-backup causes. Read-only; no game files/process state changed.

## Findings

- Overstrike's own current README calls game launch crashes most frequently due to either a corrupted `toc` or corrupted save. It says Overstrike keeps `toc.BAK` as a clean baseline and explicitly names a Steam/EGS game update making the backup stale, an interrupted mod install, another tool editing files unexpectedly, or missing/incomplete files as causes of TOC corruption. The documented reset is remove both `toc` and `toc.BAK`, verify game files to restore clean TOC, then reinstall mods only after the unmodded game works. This is directly relevant to current Steam build changes and matches the user's prior reset action. Source: [Overstrike README troubleshooting](https://github.com/Tkachov/Overstrike/blob/main/Overstrike/README.txt).
- The README says a failed mod installation should leave the game unmodded and record details in `errors.log` beside `Overstrike.exe`; an abrupt process stop should show an error state. If the verified vanilla game launches but the issue returns only after Overstrike installation, its own troubleshooting points toward a mod or an installer bug. Read the newest end of `errors.log` before diagnosing a specific mod.
- Open issue list currently shows 21 issues; its only listed bug (#34, “Vortex integration: failing to find `scripts_proxy.dll`”) is from a Marvel's Spider-Man 2 setup and documents a Vortex/mod-loader conflict, not Rift Apart or TOC/boot video. The remaining visible open items are enhancements. I found no open RCRA black-screen, TOC, boot-video, or streaming issue in the repository's visible issue list. Source: [Overstrike open issues](https://github.com/Tkachov/Overstrike/issues), [issue #34](https://github.com/Tkachov/Overstrike/issues/34).
- GitHub site search for closed Overstrike issues using RCRA/Ratchet/TOC/black-screen terms did not surface a relevant closed ticket. GitHub's filtered closed-issue pages were not retrievable through the current web index, so this is not proof that no matching closed report exists.
- Latest visible GitHub release is `OS/v1.8.1` (tag commit `5829f3b`). Its notes are specifically MSM2 Suits Menu changes (including Miles suits/cutscene models/webwings), with no RCRA-specific fix or compatibility note. Release page says four commits have landed on `main` since that tag, but the change list could not be fetched by the web index; therefore don't treat the release notes as evidence of current-main changes. Source: [Overstrike v1.8.1 release](https://github.com/Tkachov/Overstrike/releases/tag/OS%2Fv1.8.1).
- Current official Quickstart repeats the TOC-reset procedure and emphasizes testing vanilla first; it describes Overstrike as supporting RCRA and notes install errors should be in `errors.log`. Source: [Overstrike Quickstart](https://github.com/Tkachov/Overstrike/blob/main/Overstrike/Quickstart.txt).

## Most plausible cause and discriminating check

The strongest repository-supported lead is a stale or damaged `toc`/`toc.BAK` pair, especially if the Steam update happened while Overstrike's backup still reflected the previous build, or if the earlier mod install was interrupted. Since Steam verification/reset has already been performed, the next clean discriminator is: confirm the verified unmodded game launches before installing mods; if it does, inspect the current Overstrike profile's enabled mod list and newest `errors.log`, then install the smallest/empty mod set once and check the game's `toc`/`toc.BAK` timestamps and backup freshness. If vanilla itself still black-screens after reset, Overstrike is not established as the cause by these sources.

No GitHub issue or release note ties Overstrike 1.8.1 specifically to a Rift Apart black screen, boot video, or streaming regression. The boot/movie path is a separate game-native concern; this audit found no Overstrike-native skip/video report supporting that attribution.
