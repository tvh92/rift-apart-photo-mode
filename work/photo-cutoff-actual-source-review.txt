1. Replay semantics (0x10B9A50 dump)
- 0x10B9BEE mov rax,[rsp+38h]; 0x10B9BF3 je 0x10B9C0D; 0x10B9BF5 mov rdx,rax; 0x10B9BF8 mov rcx,rbx; 0x10B9BFB call 0x10B9750; 0x10B9C00 comiss xmm0,[rbx+A0h]; 0x10B9C07 ja 0x10B9C99; 0x10B9C0D shr r8d,13h; 0x10B9C11 test r8b,1.
- The only way to reach 0x10B9C00 is the return from the call at 0x10B9BFB.
- 0x10B9750 (full dump, 0x10B9750..0x10B9869) writes only xmm0-7, [rsp],[rsp+10h] in its own 0x28 frame, and rsp. It never writes rax, rdx or r8. It never touches the caller's [rsp+38h], which is the callee's entry rsp+0x40, beyond its shadow space.
- So at 0x10B9C00, rax == [rsp+38h] on every path. The relay's mov rax,[rsp+38h] is value-identical. The native code relies on this too (0x10B9C1B mov rdx,rax; r8d used at 0x10B9C0D after the call).
- Keep path: native "ja not taken" leaves xmm0, rax, rdx and r8 unchanged. Relay is identical except flags.
- Flags at 0x10B9C0D: SHR imm 13h writes CF/ZF/SF/PF, then TEST r8b,1 rewrites all flags before any jcc. Dead.
- Flags at 0x10B9C99: the replay path's flags come from the original comiss, so they are identical anyway. Natively, inc edi / add rsi,8 overwrite them.
- NaN/unordered comiss: ja is not taken, so the light is kept, same as native.
- Branch targets in 0x10B9C01..0x10B9C0C: none.
  - All intra-function branch targets were enumerated: 10B9B30/50/62/6A/70/90, 10B9BC6/BDD, 10B9C0D/41/69/72/8E/99/9E, 10B9CBE/CF8, 10B9D48/97.
  - work/branch-refs.bin and rip-refs.bin have no reference into 0x10B9C01..0x10B9C0C.
  - The only external refs are rip-ref 0x10BB643 -> 0x10B9A50 and the branch 0x12BBE81 -> 0x10BB270.

2. View identity
- Prologue: [rsp+38h] = [rcx+48h]+30h (0x10B9A92..0x10B9AA1).
- 0x10BB270 builds the 0x48-byte argument block at rsp+0B0 with fields r15, rbp, rbx, r14, ... (0x10BB5BA..0x10BB611). It submits the job via 0x107B4B0 with fn 0x10B9A50 (0x10BB643).
- The job function reads ctx+30 = r15 (source pointer array, rsi), ctx+38 = rbp (request: [+8] output, lock xadd [+10] count, matching 0x10BB2F8/2FC), ctx+40 = rbx (occlusion ctx, r13), ctx+48 = r14. This confirms the arg block is at ctx+30 and ctx+48 = r14 = rcx of 0x10BB270.
- The caller 0x12BB640 passes rdi = its own rcx, the view object (+1FE8/+1FF0/+1BD0 view fields), at 0x12BBE7E.
- Comparing [game+6739B10]+30 with [rsp+38h] is therefore exactly "job view == persistent primary view". This is the same identity PhotoLight.h and the fog wrapper use. It is meaningful.
- A null global gives 0x30, which cannot match a real view+30.

3. Thread safety
- The exchange is an aligned 8-byte CMPXCHG8 (0x10B9C00 is 8-aligned, within one cache line), done once at install. All other threads are suspended.
- Possible interrupted instruction boundaries in the window are 0x10B9C00 and 0x10B9C07. Both lie in the refused [site, site+9) range, which also covers 0x10B9C08.
- A thread suspended inside 0x10B9750 returns to 0x10B9C00 and executes the new JMP, which is fine. RIP 0x10B9C0D is past the window, also fine.
- Unused sites[1].site=NULL gives the harmless range [0,9).
- Residual risk (same as the already-installed geometry/light/specular hooks): a thread created after the Toolhelp snapshot is not suspended. If it sat at exactly 0x10B9C07 during the swap, it would decode NOP + "87 8C ..." garbage. Probability is very low and was accepted before. Not new.

4. Unwind
- Identical pattern to PhotoLight.h.
  - A CHAININFO v1 (0x21, 0 codes) chains to a copy of the native fragment entry 0x10B9AED..0x10B9D48. That entry is itself 0x21 and chains to the root 0x10B9A50 (fixture rows confirm).
  - The relay makes no rsp/nonvolatile changes and no calls.
  - Chain at page+256 (16 bytes), table at page+288; no overlap with the 112-byte code.
- The relay exits with E9 rel32 (offset 84, offset 107) rather than PhotoLight's register jmp.
  - The Windows epilog heuristic treats a jmp rel32 outside the function as an epilog unless RtlpSameFunction resolves the target to the same primary function.
  - Here the target 0x10B9C0D resolves to fragment 0x10B9AED, whose primary is 0x10B9A50, which is also the relay's primary.
  - The probe's unwind_matches covers all 19 instruction starts, including offsets 84 and 107, and passes on this Windows 10 19045. It would differ if the starts were misdetected as epilogs.
  - Non-blocking. Optional hardening: use `mov r11,imm64; jmp r11` (as GeometryLOD does), but only if R11 is proven dead. Not required.
